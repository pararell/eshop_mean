# Changelog

All notable changes to this project are documented in this file. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/). Entries up to 0.9.2 were generated by standard-version.

## Unreleased

### Added

- **Admin Overview** (`/:lang/dashboard`): revenue and orders for today, 7 or 30 days per currency,
  compared with the previous period; average order; orders to handle; revenue per day (one bar chart
  per currency, with a table view); top products; recent orders; what needs attention (visible but
  unavailable products, missing texts per language, missing meta descriptions, untranslated shop
  texts); AI draft usage and estimated cost. Served by the new read-only `GET /api/admin/overview`.
- **Admin frame:** grouped sidebar (Overview, Catalog, Sales, Content, Appearance, Settings),
  collapsible and remembered, an icon rail on tablets and a slide-in menu on phones; top bar with
  breadcrumbs, product search (`/` focuses it), View shop, light/dark switch and account menu; skip
  link. Every admin page has its own URL (`/dashboard/products`, `/categories`, `/pages`, `/themes`,
  `/config`, `/translations`, `/orders`).
- Accessibility checks (axe, WCAG 2.1 AA) for every admin page and open editor in light and dark mode,
  run by the e2e suite.
- **Home page:** a benefits strip under the hero (free shipping from the shop config's limit, cash on
  delivery, 14-day returns, secure payment) and a promo banner (photo, title and text per language,
  link) set up in the theme editor (Themes → Promo banner).
- **Theme settings:** the shop name (header, footer, page titles, structured data; empty keeps the
  `ESHOP_TITLE` translation) and the hero photo colors (original or a warm tint). Stored in the theme's
  `styles`, no schema change.
- Accessibility checks (axe, WCAG 2.1 AA) for the home page and product list in light and dark mode.

### Changed

- **Brand accent:** forest green (`#15803d` light, `#4ade80` dark; WCAG AA) is the default brand color,
  used for primary buttons, sale prices and SALE badges, the active menu item, links, focus rings and
  hover states. A theme's primary color still overrides it.
- **Category tiles:** the photo fills the tile with the name over a dark gradient; five categories are
  laid out as one large and four small tiles, other counts in rows without a lone tile.
- **Product grid:** tighter rows, larger bold prices aligned at the bottom of each card, sale prices in
  the accent with the old price struck through in gray.
- **Sale price validation:** a product on sale needs a sale price below its regular price, in the
  product editor and in the API (`POST /api/products/add`, `PATCH /api/products/edit` answer 400).
- **Admin pages redesigned** with shared patterns: page header with the main action, list + editor
  layout with search, sections and language tabs, sticky save bar with an unsaved-changes state,
  confirmation before deleting, success and error messages after saving (saves used to answer
  "Request sent" whatever happened), empty and loading states.
  - Categories, pages, themes and shop configs are picked from a list instead of typing their slug;
    shipping fields say what they mean (standard/bulky, cost, free from) in each language's currency.
  - Translations: one table with a column per language, search, "missing only", add/remove keys and
    a validated JSON mode.
  - Orders: a table with search, status filter, sorting and paging.
- **Admin dark mode:** every admin color comes from the design tokens (about 40 hard-coded colors
  replaced); form controls have 3:1 borders; the rich-text editor uses TinyMCE's dark skin in dark mode.

### Fixed

- Admin "View shop" and sign-out went to `/en` (no such route), which redirected to the 404 page; they
  now open the home page `/` in the current language.
- **BUG-08:** creating a product or category through its edit endpoint (an upsert) answered 404
  although it was saved; it now answers 200.
- Admin text that was unreadable in dark mode (light text on hard-coded white panels).
- Server-side rendering errors on the admin categories page.
- A late answer of the shop's page-title request could replace the admin's full page list, so
  saving a page could have erased its content.
- The axe checks of the checkout skipped content in the app's scroll container; they now see it.

## [1.0.1](https://github.com/pararell/eshop_mean/compare/v1.0.0...v1.0.1) (2026-10-25)

### Added

- **Build info:** the running version, short git SHA and build date are printed once in the browser
  console (`Eshop v1.0.0 · a1b2c3d · 2026-10-24`), shown at the bottom of the admin dashboard and
  answered by `GET /api/version`. They are compiled in by `npm run build:ssr`; Docker builds take
  them as build arguments:
  `docker buildx build --build-arg GIT_SHA=$(git rev-parse --short HEAD) --build-arg BUILD_DATE=$(date -u +%F) …`.
  Without them (or in `ng serve` / `nest start`) the fields read `dev`.
- `npm run email:preview` renders every email with sample data into `test-results/email-preview/`.
- E2E contrast checks (axe, WCAG AA) for the cart and checkout in light and dark mode.

### Changed

- **Order and contact emails redesigned:** responsive, table-based HTML (Gmail, Outlook, Apple Mail,
  phones) with a plain-text alternative, readable in email dark mode, in the customer's language
  (built-in English, Slovak and Czech texts). Customers get an order confirmation (items with
  photos, subtotal, shipping, total, payment method, address, link to the order); admins get a
  separate new-order email with the customer's contact, a dashboard link and `Reply-To` set to
  the customer. The contact form sends a copy to the sender and a notice to the admins.
  Subjects are now descriptive (`Your order … at …`, `New order … · total`) instead of `Order` /
  `Contact`. Still sent through Resend; no new environment variables.
- Form controls (inputs, radios, payment choices) use a new `--color-border-control` token with
  3:1 contrast; disabled buttons are a readable grey instead of a faded primary color.

### Fixed

- **Checkout in dark mode:** the Stripe Payment Element is styled from the design tokens (Stripe's
  `night` theme in dark mode) and follows the light/dark switch without a reload; the Pay button
  uses the shop's button styles and stays visible when disabled.

### Security

- **Dependency fixes** (`npm audit` now reports 0 vulnerabilities, production and development):
  - `body-parser` 2.3 → 2.4.0: denial of service via trailing bytes after a compressed request body.
  - `multer` 2.4 → 2.5.0: denial of service via a pending asynchronous `fileFilter`. NestJS pins
    2.4.0, so a `package.json` override applies our version (see CLAUDE.md § Dependency overrides).
  - `zod` 4.6.5 → 4.6.6 (memory exhaustion on oversized collections) through `@angular/cli` 22.2.4;
    used only by the Angular CLI, not by the app.
  - Development tooling: Angular CLI/build 22.2.2 → 22.2.4, `vite` 8.3.0 → 8.3.5 (override:
    dev-server file exposure, `launch-editor`), `undici` 8.12.3, `fast-uri` 3.1.9, and esbuild 0.25 for
    drizzle-kit's loader (override).
- **Image uploads are bounded on the server** like in the editor: one file, at most 10 MB,
  JPEG/PNG/WebP/GIF (413 / 415 otherwise). Before, any size and type was buffered in memory.
- Customer input (name, address, notes, contact message) and product titles are HTML-escaped in
  emails; before, they were inserted as raw HTML.

## [1.0.0](https://github.com/pararell/eshop_mean/compare/v0.9.2...v1.0.0) (2026-10-24)

### Highlights

- **PostgreSQL 18** replaces MongoDB (Drizzle ORM, SQL migrations applied at container startup).
- **AI product drafts:** a photo and a few words become a product in every shop language
  (DeepSeek by default, Gemini or Claude).
- **Stripe Payment Element** with webhooks and refunds, **Resend** for email.
- **Redesign:** a minimal storefront with dark mode, a one-page checkout and a new admin product editor.

### Breaking changes

- **Database:** MongoDB is no longer supported; the app needs PostgreSQL 18. There is no data
  migration: products, categories, users, orders and sessions start empty.
- **Email:** Resend replaces SendGrid.
- **Card payments:** Stripe PaymentIntents and webhooks replace the token/Charges flow;
  `POST /api/orders/stripe` answers 410.
- **Environment variables:** `MONGO_URI`, `SENDGRID_KEY` and `STRIPE_PUBLISHABLE_KEY` are removed;
  `DATABASE_URL`, `RESEND_API_KEY` and `STRIPE_WEBHOOK_SECRET` are new and required.
- **Content-Security-Policy is enforced:** third-party scripts, frames or APIs that are not in the
  policy are blocked.
- **Runtime:** Node.js 24.15 or newer. The Docker image runs as the `node` user and starts
  `node dist/eshop/server/server.mjs` directly (no `npm start`).

#### Upgrading from 0.9.x

1. Create a PostgreSQL 18 database and set `DATABASE_URL`, for example
   `postgres://eshop:<password>@127.0.0.1:5432/eshop`. Remove `MONGO_URI`.
2. Create the schema and the first admin:
   `SEED_ADMIN_EMAIL=… SEED_ADMIN_PASSWORD=… npm run db:migrate && npm run db:seed`.
   Later images apply new migrations themselves at startup (`DB_MIGRATE_ON_START=false` turns that off).
3. Recreate the catalog in the dashboard; customers sign up again. Existing sessions and carts are gone.
4. Email: create a Resend account, verify your sending domain, set `RESEND_API_KEY` and
   `EMAIL_FROM` (an address on that domain). Remove `SENDGRID_KEY`.
5. Stripe: add a webhook endpoint `https://<your-shop>/api/payments/webhook` for the
   `payment_intent.*` and `charge.refunded` events and set `STRIPE_WEBHOOK_SECRET`. Keep
   `STRIPE_SECRETKEY` and `FE_STRIPE_PUBLISHABLE_KEY`; remove `STRIPE_PUBLISHABLE_KEY`.
6. Behind a reverse proxy, set `TRUST_PROXY=1` (real client IPs for rate limits, `Secure` cookies).
7. If a custom third-party script stops working, add it to the CSP in `server/src/setAppDB.ts`,
   or set `CSP_REPORT_ONLY=true` as a temporary escape hatch.
8. Optional: AI product drafts need `DEEPSEEK_API_KEY` (or `AI_PROVIDER=gemini` / `anthropic` with
   its key). See [docs/ai.md](docs/ai.md).

### Added

- **AI product drafts** ("Fill with AI"): title, descriptions, attributes, SEO texts and category
  suggestions in every shop language, from photos and a short note. DeepSeek (default), Gemini or
  Claude behind one provider interface with structured output; validated, sanitized, never saved
  automatically and never sets price or stock. Retries when the provider is busy, writes the
  admin's language first, and logs tokens and estimated cost in `ai_usage`. Off without an API key.
- **Admin product editor** on its own page: drag-and-drop photos, ordering and main photo, category
  chips, per-language tabs, validation, a sticky Save bar and an unsaved-changes guard.
- **Admin product table** with search, filters, sorting and paging.
- **Card payments** with the Stripe Payment Element (3-D Secure, Google Pay), signature-verified
  webhooks, new order statuses (`PENDING_PAYMENT`, `PAYMENT_FAILED`, `REFUNDED`) and full or partial
  refunds from the admin order detail.
- **SEO title and meta description** per product language.
- **Dark mode** (follows the system, with a toggle) and a new minimal design: transparent header over
  the home photo or video, contour-line pattern behind product grids, mountain-ridge footer.
- **Product gallery** with a full-screen viewer: click to zoom, drag, wheel and pinch.
- `npm run db:up`, `db:migrate`, `db:seed` and `db:generate`; a `docker-compose.yml` for a local database.
- Tests: Jest + Supertest API and unit tests against a disposable PostgreSQL, Playwright e2e tests
  against the production build. External services are stubbed. `npm run docs:media` regenerates the
  README screenshots.
- Docs: architecture, database runbook, testing, AI, payments, audit and decision records.

### Changed

- Angular 20 → 22 (zoneless, standalone, signals, strict templates), NestJS 11 → 12 on Express 5,
  TypeScript 5.8 → 6 with `strict` everywhere, Stripe SDK 9 → 23.
- One-page checkout instead of the stepper.
- Product and category images are shown whole (no cropping) on a white tile, with responsive
  Cloudinary sizes (`f_auto`, `q_auto`).
- The language is always in the URL (`/en`, `/sk`, `/cs`); `<html lang>` follows it, also in SSR.
- Product images are saved with the product on Save instead of immediately on upload.
- Docker image: 783 MB → 175 MB, non-root, `tini` as PID 1; Node.js 24.21 on Alpine 3.24.
- One ESLint flat config and Prettier for the whole repo, with a pre-commit hook.

### Fixed

- Stripe amounts are rounded to whole cents.
- The currency is derived on the server from the language; the client value is ignored.
- A failed order keeps the cart; a failed sign-in no longer logs the user out.
- Sign-in no longer applies the sign-up password rules to existing passwords.
- Language URLs: the server renders the language of the URL, the switcher changes the URL prefix, and the home page remembers the last chosen language.
- Saves and deletes in the admin refresh the lists; unhandled promise rejections are caught and logged.
- Accessibility: names for icon buttons and links, `alt` texts, a pause button for the home video.

### Removed

- MongoDB, Mongoose and connect-mongo; `MONGO_URI`.
- SendGrid (`@sendgrid/mail`, `SENDGRID_KEY`).
- The Stripe token/Charges checkout and `STRIPE_PUBLISHABLE_KEY`.
- The home carousel, the checkout stepper and the old "Add/Edit product" admin tabs.
- `standard-version` and `npm run release`: releases use `npm version`.
- Unused dependencies (`deepmerge`, `fastify-static`, `ts-node`, `@nestjs/serve-static`, …).

### Security

- Dependency upgrades fix the known vulnerabilities of 0.9.x (the old database driver, Angular, NestJS).
- helmet security headers and an enforced Content-Security-Policy with a per-request nonce.
- Per-IP rate limits on sign-in, sign-up, contact and order endpoints (`RATE_LIMIT_PER_MINUTE`).
- Session cookie `httpOnly`, `SameSite=Lax`, `Secure` over HTTPS.
- Sign-up stores only whitelisted fields; passwords are checked with `bcrypt.compare`.
- Search uses escaped `ILIKE` patterns instead of user-supplied regular expressions.
- SSR renders only for allowed hosts; `.env` files are never copied into the Docker image.
- AI output is treated as untrusted (validated, HTML sanitized); API keys stay on the server.
